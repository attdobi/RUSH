Reinforcement learning Using SME feedback and High-reasoning models

Cheap models label. Hard cases escalate. SMEs decide — and the policy learns.

A panel of low-cost models labels everything against an SME-owned policy graph; disagreements climb to a high-reasoning judge, the residue goes to experts, and every accepted ruling becomes the next policy version. Decision quality grows run over run.

The RUSH loop

Pick the judges. Turn the crank. Watch the policy learn.

Every run is numbered and seeded, and starts from the same fixed generator (k=0 = policy v0.1). Each cycle: a seeded train mini-batch → the most instructive misalignments become anchors → one policy edit (≤5 changes, human-reviewable) → scored on the run's fixed test partition → the gate accepts only if the system-of-judges macro-F1 improves (a gate agent can veto, never force — or switch the gate off to watch unfiltered drift). Accepted edits become new policy-graph nodes below. You audit the gate afterward — every verdict is training data for the critic.

How this works — judges vs drafter vs gate (and what costs money)

Judges — your panel. The 2–5 cheap models below label every image and score every metric. All decision-quality numbers on this page — F1 before/after, the learning curve, the gate metric — come from THIS panel. No expensive model ever scores quality.

Drafter — the optimizer. Once per cycle, one model looks at the most instructive misaligned images (the actual pixels are attached to its prompt) and writes ONE policy edit of at most 5 node files. A cheaper drafter is a legitimate choice — it drafts, it never judges. "Anchors" picks how the misalignments are chosen: an unbiased random sample, or top-gradient (confident-wrong panels first, |g| = 1−p).

Gate — a deterministic rule. An edit is accepted only if the panel's test-partition macro-F1 strictly improves. Optionally an expensive gate agent double-checks and can VETO a suspicious win — it can never force one — and every rationale it produces is reported in the gate ledger below.

Cost. Each cycle labels N train + T test images with every judge; the benchmark readout adds two passes over the fixed 1,000-image validation split. Accepted versions are named v<run>.<k> — run 5 accepting at cycle 3 mints v5.3.
