Reinforcement learning Using SME feedback and High-reasoning models

Cheap models label. Hard cases escalate. SMEs decide — and the policy learns.

A panel of low-cost models labels everything against an SME-owned policy graph; disagreements climb to a high-reasoning judge, the residue goes to experts, and every accepted ruling becomes the next policy version. Decision quality grows run over run.

The RUSH loop

Pick the judges. Turn the crank. Watch the policy learn.

Every run is numbered and seeded, and starts from the same fixed generator (k=0 = policy v0.1). Each cycle: a seeded train mini-batch → the most instructive misalignments become anchors → one policy edit (≤5 changes, human-reviewable) → scored on the run's fixed test partition → the gate accepts only if the system-of-judges macro-F1 improves (a gate agent can veto, never force — or switch the gate off to watch unfiltered drift). Accepted edits become new policy-graph nodes below. You audit the gate afterward — every verdict is training data for the critic.

How this works — judges vs drafter vs gate (and what costs money)

Judges — your panel. The 2–5 cheap models below label every image and score every metric. All decision-quality numbers on this page — F1 before/after, the learning curve, the gate metric — come from THIS panel. No expensive model ever scores quality. Every batch is compliance-checked: a judge emitting a near-constant label is flagged non-compliant and (by default) deweighted — its votes leave the majority vote and the optimizer signal, because no policy edit can fix a judge that isn't reading the policy.

Drafter — the optimizer. Once per cycle, one model reads the most instructive misaligned anchors and writes ONE policy edit of at most 5 node files. A cheaper drafter is a legitimate choice — it drafts, it never judges. "Input" picks what it reads per anchor: text fields only (default — each judge's label, confidence, difficulty, boundary flag, and justification, plus the SME truth) or images + text, which also attaches the anchor pixels for visual boundary cases at extra token cost. "Anchors" picks how the misalignments are chosen: an unbiased random sample, top-gradient (confident-wrong panels first, |g| = 1−p), or top-importance (the four-tier misalignment × consensus rank — see the About tab).

Gate — four modes. Default: a deterministic rule — an edit is accepted only if the panel's test-partition macro-F1 strictly improves. "+ agent" keeps that rule as the hard wall and lets a gate agent VETO a suspicious win (never force one). "Critic agent only" hands the decision to the agent: the metric is reported as advisory evidence but not enforced, so the critic may accept a metric-flat edit it judges sound — the arm that tests LLM judgment against the metric rule (agent failure falls back to the metric rule). OFF accepts everything. Every rationale is reported in the gate ledger below.

Cost. Each cycle labels N train + T test images with every judge; the benchmark readout adds two passes over the fixed 1,000-image validation split. Accepted versions are named v<run>.<k> — run 5 accepting at cycle 3 mints v5.3.

Cross-run benchmarks

Every run on the same yardstick.

One row per live run of the active demo: its configuration knobs and its start → final system macro-F1 on the fixed validation benchmark — the same images every run, never used for training or gating, so runs, anchor strategies, gate modes, and drafters compare honestly. The locked-holdout readout is shown alongside when a run paid for it. Runs without a benchmark readout show a dash — tick Benchmark readout on the run form to get one. Dry runs are excluded (fake labels would fake the numbers).
